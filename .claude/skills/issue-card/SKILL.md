# 问题卡片

内网发不了网，问题卡片靠**拍照**带出公网、贴进 dbdog-release 的 issue。
因此输出必须：短（一屏内）、结构化、绝无敏感信息。

## 流程

1. 问清三件事（用户已说清的不重复问）：现象（含关键报错的**摘要**）、
   最小复现步骤、期望行为。
2. 跑 `scripts/fingerprint.sh --oneline` 取环境指纹。
3. 按下面模板输出，整体 ≤ 18 行，放在一个代码块里方便拍照：

```
【dbdog 问题卡片】<一句话标题>
指纹: <fingerprint --oneline 输出>
现象:
  <2-4 行，报错取关键行改写，不贴原始日志>
复现:
  1. <步骤>
  2. <步骤>
期望: <1-2 行>
备注: <可选：出现频率、影响面>
```

## 红线（仓库是公开的）

- 不出现：内网 IP/主机名/域名、账号、密钥、连接串、业务数据样本、单位名称。
- 报错信息**改写摘要**，不整段照抄（路径里常藏主机名和用户名）。
- 生成后主动做一次敏感信息自查再交给用户。
