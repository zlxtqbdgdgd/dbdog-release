1. 改之前是什么样

远端 main 仍是旧状态 本地曾做后被 reset 丢掉过

改造前的权威状态就是现在的 origin/main（d804ed3， publish: dbdog-web@0.1.12）。特征如下：

  • manifest 八列：module / kind / target / service / version / artifact / sha256 / source_sha，没有架构列。
  • 事实上一架构：Agent 与大多数模块只发 aarch64；安装侧也按 AArch64 假设工作。
  • 没有 ddprof 模块：原生 Continuous Profiling 的官方二进制尚未进入 release manifest。
  • 发布事务按模块逐架构即时上传改表：不足以保证「同模块多架构原子一次提交」。
  • 没有数据库主机一键部署的权威设计落盘：docs/design/ 下的总设计与三份实施计划还不在 main 上。

2. 我们要改的是什么

总设计把「数据库主机一键部署 + 原生 profiling」拆成三个连续计划，避免一次改发布格式、数据库接入和生命周期：

阶段 计划文档 目标 状态
Plan 1 2026-08-02-multi-architecture-release-foundation.md manifest v2、多架构发布事务、ddprof、Agent x86_64、目标机按 arch 选包 代码基本完成，正式发布未做
Plan 2 2026-08-02-database-host-dbm-deployment.md 三引擎发现、DBM 安装事务；不改数据库启动链 仅有计划
Plan 3 2026-08-02-native-profiling-lifecycle.md launcher / CM / systemd 生命周期与 profiling 事务 仅有计划

Plan 1 的合同（要改成的形态）

  • manifest 九列，主键 (module, arch)；取值只允许 aarch64 / x86_64 / noarch。
  • 目标机精确选本机架构；只有显式 noarch 才回退。
  • 同一模块全部目标架构构建、校验、上传完成后，才一次更新 manifest/README 并提交。
  • 官方 ddprof v0.26.0 双架构进入 release，不重新编译。
  • Agent aarch64/x86_64 同源码锚、同版本，经原生 builder 出货。
  • 提供只读 artifact 冒烟：DBDOG_AGENT_PREFLIGHT_ONLY=1。

4. 还剩什么

Plan 1 Completion Gate 未过 Plan 2 / 3 未开工

A. 环境与权限（堵住正式发布）

  • builder SSH：dbdog-build / dbdog-build-x86 当前连接被对端关闭。
  • 远端写权限：当前账号对 zlxtqbdgdgd/dbdog-release push 被拒。

B. Plan 1 尚未执行的操作（Task 7）

  1. 把本分支合入 / 推到可作为发布基线的 main。
  2. publish.sh publish ddprof --yes —— 双架构真实上传并替换声明行。
  3. publish.sh publish dbdog-agent --bump patch --yes —— 同版本 aarch64/x86_64 原子发布。
  4. 在 aarch64 / x86_64 测试机跑： sudo DBDOG_AGENT_PREFLIGHT_ONLY=1 ./scripts/upgrade.sh dbdog-agent
  5. 刷新 agent-history，跑全量合同测试 + prune 闭环。

C. 后续计划（Plan 1 完成后再做）

  • Plan 2：数据库主机 DBM 一键部署（发现 / 选择 / managed-files / 三引擎适配）。
